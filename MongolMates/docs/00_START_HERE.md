# 00 · START HERE（从这里开始）

本系统用于管理原创 IP《蒙古萌友》（Mongol Mates）的三套微信静态表情包，共 48 个表情位。

## 三条铁律

1. **图片是最终依据**：现有图片是角色外观的最终依据，文字规范只负责描述和约束。不能用重新生成的“相似角色”替换原版。任何未确认的图片都不能自动标记为正式母版。
2. **成图优先**：已制作表情的标题和文案按成图登记。角色外观以用户确认的母版或修订为准。
3. **两版一包**：每套只交付 `original/`（原生高清）与 `240x240/` 两套 PNG，独立 ZIP；少量修复只交付被修改的图片。

## 四类角色任务

| 任务 | 入口文档 | 说明 |
| --- | --- | --- |
| 新制作表情 | CHARACTER_BIBLE、ART_STYLE_GUIDE、COMPOSITION_GUIDE | 先确认角色母版，再制作 |
| 局部修复 | IMAGE_EDITING_RULES | 只改指定区域，保留其余 |
| 导出与打包 | DELIVERY_STANDARD | 两版 ZIP + verify_zip |
| 检查验收 | QA_CHECKLIST、BACKGROUND_AND_OUTLINE | 技术 + 视觉双层 |

## 接手流程

1. 读 `AGENTS.md` 与 `config/*.yaml`。
2. 读目标角色档案与目标表情元数据。
3. 判断任务类型：新制作 / 局部修复 / 导出。
4. 用工具（`tools/`）执行；不要用图片重生成代替局部编辑。
5. 生成对比预览 → QA 检查 → 用户确认 → 更新母版与版本 → 导出打包。

详细流程见 `AI_WORKFLOW.md`；常见错误见 `ERROR_CASES.md`。
