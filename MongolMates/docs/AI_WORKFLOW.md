# AI 工作流 AI_WORKFLOW

## 跨 AI 使用规则

本项目**不依赖任何一个 AI 的历史聊天记录**保持一致性。跨 AI 传递的最小标准资料包：

1. 项目基础规范（本套 docs + config）。
2. 对应角色的 Character Bible。
3. 对应角色的官方母版（若无，明确说明“尚无确认母版”）。
4. 2～4 张最接近本次任务的已审核表情。
5. 本次目标动作与文字。
6. 禁止修改项。
7. 输出规格。

只上传当前任务需要的角色参考，不必把所有历史图都给 AI。必须区分**已批准母版**与**普通设计参考**：AI 只能参考后者的姿势/表现/场景，不能因此改变正式角色核心特征。

对不支持 AGENTS.md 或 Skill 的 AI，提供通用 Markdown 文档 + 参考图即可。若某 AI 无法准确遵守角色结构，应停止无意义重复生成，改为局部编辑、参考图控制或人工绘制。

## Skill 职责

`skills/mongol-mates-director` 负责：读规范 → 读角色母版 → 读表情元数据 → 判断任务类型（新制作/局部修复/正式导出）→ 准备参考与约束 → 检查角色一致性 → 检查背景与白边 → 检查文字与结构 → 管理审核状态 → 生成两版 → ZIP 打包验证 → 更新版本记录。

Skill 必须调用项目规范，不得复制出冲突规则。

## 标准作业流程

```
读 AGENTS.md + config
      ↓
读角色档案 + 表情元数据
      ↓
判断任务类型
   ├─ 新制作 → 参考 CHARACTER_BIBLE + 已审核同角色表情
   ├─ 局部修复 → 走 IMAGE_EDITING_RULES 七步法
   └─ 导出 → 走 DELIVERY_STANDARD
      ↓
产出候选（working/candidate，绝不直接 approved）
      ↓
生成对比预览 → QA 检查
      ↓
用户确认 → 更新母版 + CHANGELOG
      ↓
导出两版 → 打包 → verify_zip → 提供下载链接
```

## 审核状态流转

`imported → needs_review → working → candidate → approved`（或 `rejected` / `archived`）。

- `approved` 只能由用户明确确认产生，工具不得自动置位。
- 当前所有图片处于 `needs_review`。

## 初始化阶段纪律

先建系统，不批量改图。初始化时不得擅自重新生成、替换或修改已有角色图片；缺素材就记录缺失并继续建设规范/目录/工具，不编造素材、不用其他图片代替。
