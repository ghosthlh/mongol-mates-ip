# 交付标准 DELIVERY_STANDARD

## 两版规格

### 原生高清版 `original/`

- 新表情直接在原生高清尺寸制作，保留原始 PNG 和生成或绘制来源。审核通过后，再从这张图导出 240×240 版本。
- 旧高清版本如有质量问题，暂缓作为母版。已制作表情的文案和构图以现有成图为准。
- 不通过简单放大低清图片冒充原图。
- 普通表情透明背景；复杂场景白色不透明背景。
- 优先保留 1200×1200 或更高原生尺寸；若原生仅 1024px 则记录 1024px；若原生仅 240px，不得放大导出成 `original` 的 1200px 文件。
- 缺高清母版标记 `missing_native_master`，不得通过正式高清交付验收。

### 微信尺寸版 `240x240/`

- 240×240 PNG，从已确认母版缩小（Lanczos，保持 1:1，不拉伸变形）。
- 普通表情保留透明通道；复杂场景保留白底。
- 单张原则 < 500KB。
- 缩小后若文字模糊、白边断裂、细节丢失，进行专门的缩小尺寸优化。
- 不得把低清微信表情反向放大作正式母版。

## ZIP 交付

每次只交付一套系列。例：`MongolMates_Vol03_Reactions_v1.0.zip`

```
MongolMates_Vol03_Reactions/
├── original/    (16 张)
└── 240x240/     (16 张)
```

一套 16 张正常含 32 个 PNG 文件。不同系列不得混入同一正式发布 ZIP。

局部修复：只打包本次修改表情，例 `MongolMates_Vol03_Patch_01_11_v1.1.zip`（01 与 11 各含两版），不得重新加入其他 14 张。

## 打包前自动检查

- ZIP 真实存在、可正常打开、可完整解压。
- 文件数量符合本次任务范围。
- 两目录中的文件均须为可解码的 PNG，编号一一对应。
- `original/` 长边至少 600px，与导出工具的尺寸检查一致。入库审核需另行确认来源，尺寸检查无法证明原生。
- 240px 版全部 240×240。
- 原生高清版有真实来源记录。
- 背景模式与规范一致。
- 无重名、空文件、多余系统文件。
- 完成后提供可点击 ZIP 下载链接，不能只输出普通文件路径。

工具：`package_series.py` / `package_patch.py` 打包，`verify_zip.py` 校验。

## 附属素材（不属于标准 ZIP）

表情封面 240×240（透明）、聊天页图标 50×50（透明）、详情页横幅 750×400、赞赏引导图 750×560、赞赏致谢图 750×750。除非用户明确要求，否则不纳入 16 张 ZIP。横幅不得压扁、拉宽人物或使比例失真。
